# R10/R11 — Correctifs complets, 15 octobre 2026

Ce bilan remplace le statut partiel du premier lot. L’utilisateur a demandé de traiter les points laissés ouverts. Les corrections sont locales ; ce document ne vaut pas preuve de publication.

## R10 — Dépendances corrigées à la source

L’audit npm passe de **9 entrées (5 hautes, 4 modérées) à zéro**. Tailwind est migré de 3.4.19 vers 4.3.3 avec son plugin PostCSS. Le tagger Lovable de développement, qui réintroduisait Tailwind 3, est retiré. Le plugin typographique est retiré après contrôle de l’absence de classes `prose` dans les 13 148 pages du sitemap généré. Aucun avis n’est ignoré et aucun paquet vulnérable n’est renommé pour masquer l’audit.

Les tokens et la configuration ToolTrim sont conservés. Un traitement PostCSS testé rétablit l’ordre de cascade v3 : sans lui, les couches natives v4 modifiaient la priorité de plusieurs composants. Les renommages officiels des utilitaires préservent les petites ombres, les flous et le focus. `tailwind-merge` 3.7.0, [compatible avec Tailwind 4](https://github.com/dcastil/tailwind-merge), remplace 2.6.0 ; un test rouge a reproduit le conflit d’outline avant cette mise à jour.

Le premier lot avait omis l’usage de SWC dans `vitest.config.ts` : les modules partagés avaient masqué l’erreur. Cette configuration emploie maintenant le même plugin React que Vite. L’installation indépendante évite cette fausse assurance. Le helper de corrections de liens utilise un module JavaScript partagé compatible Node 20, version de la CI.

**Portée et coût :** il s’agit d’une remédiation de dépendances, pas d’une promesse de vitesse. Le premier build intégré mesure 153 632 octets gzip de CSS principal contre 132 572 auparavant ; Tailwind 4 conserve davantage de règles de composants. Le premier build Node 20 a bloqué sur le budget CSS (36,3 Mio). Un préfixe commun jusque-là répété dans les fichiers critiques est maintenant partagé, en conservant exactement l’ordre préfixe → page → socle ; trois tests de reconstruction couvrent aussi les shells sans préfixe et les frontières de règles. Le build intégré suivant mesure 27,2 Mio de CSS. Les budgets existants ne sont pas relevés. Les navigateurs cibles de Tailwind 4 sont Safari 16.4+, Chrome 111+ et Firefox 128+ ([guide officiel](https://tailwindcss.com/docs/upgrade-guide)).

[Audits et graphe de dépendances](proofs/r10-dependencies-2026-10-15/).

## Vérification et statut

Build production Node 20 validé : 13 148 URLs indexables, 130 cas de routes, 784,8 Mio d’artefact dont 27,2 Mio de CSS ; budgets inchangés. Suites : 375 tests applicatifs, 39 contrats SEO/CSS, 144 tests Ma Stack et types app/Node/API validés. Les contrats API comptent 166 réussites et 18 intégrations ignorées faute de prérequis locaux ; aucune certification du backend distant n’en est déduite. Recettes réussies : 21 R11, 26 Ma Stack, 21 accessibilité, 14 paiement simulé, 57 hydratation et 19 analytics/consentement. Vingt contrôles de routes hydratées complètent cette couverture. Le détail et les limites sont dans `CHANGELOG_AI.md` et les [preuves de validation](proofs/r10-dependencies-2026-10-15/validation/summary.json). La comparaison initiale de 24 variantes (six familles de pages, FR/EN, 390/1440 px) retrouve les dimensions et styles relevés avant migration, après correction de la cascade ; il ne s’agit pas d’une affirmation d’identité pixel pour toutes les pages du catalogue.

Search Console a été consultée dans la session déjà connectée : sitemap lu avec succès le 15 octobre, guides FR/EN et une page Explorer inspectés comme indexés. Les exclusions historiques datent de relevés antérieurs. Leur disparition ne peut être décrétée par une correction locale : Google doit réexplorer les URL après publication.

Les hôtes et comparaisons personnalisées hors prérendu conservent leur fonctionnement client (200/noindex initial), sans fausse page d’accueil ; leur éligibilité et leurs états introuvables sont gérés par l’application. Les réponses distantes 403/429, erreurs temporaires ou refus de connexion ne sont pas qualifiées de liens cassés et ne justifient pas d’inventer un remplacement. Les détails et statuts sont conservés dans les preuves.

**Clôture :** les correctifs techniques R10/R11 sont traités dans ce lot ; la publication et la réexploration externe doivent être distinguées de la validation locale. Les campagnes éditoriales R5/R6, les essais utilisateurs différés et le renouvellement du jeton Redis restent dans leurs chantiers séparés.
