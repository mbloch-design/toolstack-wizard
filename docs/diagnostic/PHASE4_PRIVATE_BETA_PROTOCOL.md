# Tooltrim — Protocole Phase 4, bêta privée Créatif

> Statut : préparation autonome interne
> Date d’ouverture : 30 juin 2026
> Périmètre : verticale Créatif uniquement
> Pré-requis : G3 autonome accepté avec réserves, sans validation terrain revendiquée.

## 1. Objectif Phase 4

Valider Tooltrim avec des stacks réelles de créatifs, pas avec des fixtures ou des replays proxy.

La question centrale n’est plus “est-ce que le moteur fonctionne ?”. La question devient :

> Est-ce qu’un créatif reconnaît sa manière de travailler et repart avec une décision qu’il juge raisonnable ?

## 2. Ce que la bêta doit prouver

La bêta doit prouver quatre choses :

1. L’utilisateur comprend qu’il cartographie l’existant, pas une stack idéale.
2. La cartographie ressemble à sa réalité métier, y compris usages atypiques, IA, plugins, suites et contrats flous.
3. La restitution se lit vite et produit une première décision claire.
4. Les recommandations ne donnent pas l’impression d’empiler des outils.

## 3. Format des sessions

Chaque session dure 35 à 50 minutes.

1. Introduction neutre — 3 minutes.
2. Parcours autonome sans aide — jusqu’à 10 minutes.
3. Lecture du pré-verdict et de la restitution — 5 minutes.
4. Lecture à voix haute des trois décisions — 5 minutes.
5. Entretien semi-dirigé — 15 à 25 minutes.
6. Vérification manuelle stack/coûts — 5 minutes.

Le modérateur ne doit pas expliquer Tooltrim pendant le parcours. Il peut seulement encourager l’utilisateur à penser à voix haute.

## 4. Questions d’observation prioritaires

Pendant la session, observer :

- où l’utilisateur hésite ;
- quand il pense en outil au lieu de besoin ;
- quand une suite comme Adobe, Maxon ou Canva crée une ambiguïté ;
- si les outils IA sont oubliés, mal rattachés ou perçus comme une catégorie séparée ;
- si un outil utilisé “de travers” est capturé sans jugement ;
- si le contrat ou le plan arrive trop tôt, trop tard ou trop souvent ;
- si les trois décisions semblent utiles ou trop génériques ;
- si les preuves renforcent la confiance ou alourdissent la lecture.

## 5. Métriques G4

| Indicateur | Cible G4 |
|---|---:|
| Diagnostic actionnable | ≥ 70 % |
| Fidélité perçue de la cartographie | ≥ 85 % |
| Complétion après choix Créatif | ≥ 70 % |
| Temps médian jusqu’au pré-verdict | ≤ 8 minutes |
| Utilisateurs citant une question répétitive | ≤ 15 % |
| Utilisateurs pensant recevoir une recommandation pendant la capture | 0 |
| P0 ouverts | 0 |
| P1 ouverts | < 3 |

## 6. Définition d’un diagnostic actionnable

Un diagnostic est actionnable si l’utilisateur peut citer, sans reformulation du modérateur :

- une décision concrète ;
- l’outil, usage, contrat ou risque concerné ;
- pourquoi cette décision a du sens ;
- ce qu’il ferait dans les 7 prochains jours.

Exemples acceptés :

- “Je vais vérifier si mon Adobe All Apps est vraiment payé par moi ou par l’équipe.”
- “Je vais garder Figma mais arrêter de traiter FigJam comme un outil séparé.”
- “Je vais tester un vrai workflow de validation client avant d’ajouter un outil.”
- “Je ne vais pas remplacer InDesign tout de suite, mais je vais tester une étape UI dans Figma car ça frictionne.”

## 7. Règles de tri des retours

- P0 : bloque la fin, perd des données, coût dangereusement faux, recommandation dangereuse.
- P1 : fausse la cartographie, crée une contradiction score/décision, duplique un outil/contrat, casse la confiance.
- P2 : ralentit, wording ambigu, preuve difficile à trouver, friction contournable.
- P3 : préférence visuelle, amélioration de confort ou enrichissement non bloquant.

Seuls P0 et P1 peuvent interrompre la bêta.

## 8. Décisions interdites pendant la bêta

Règle absolue : ne pas ouvrir Tech, Conseil, Content ou Ops tant que G5 Créatif n’est pas atteint.

Pendant Phase 4, ne pas :

- ouvrir Tech, Conseil, Content ou Ops tant que G5 Créatif n’est pas atteint ;
- enrichir le catalogue pour “faire passer” une session ;
- corriger un P2 isolé avant d’avoir vu s’il se répète ;
- transformer un usage atypique en anomalie ;
- ajouter des recommandations sans preuve terrain ;
- modifier le moteur de scoring sans exemple concret observé.

## 9. Porte G4

G4 ne peut être accepté que si :

- 12 sessions minimum sont jouées ;
- les 6 familles créatives sont couvertes ;
- les métriques G4 atteignent les seuils ;
- aucun P0 n’est ouvert ;
- moins de trois P1 restent ouverts ;
- les principaux abandons sont compris ;
- les corrections retenues sont classées avant Phase 5.

Tant que ces conditions ne sont pas réunies, la seule décision possible est : **Phase 4 préparée, G4 non accepté**.
