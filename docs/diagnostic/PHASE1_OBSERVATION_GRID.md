# Tooltrim — Grille d’observation Phase 1

> À copier pour chaque session utilisateur.
> Objectif : observer si le parcours Créatif candidat est compris sans explication du modèle Tooltrim.

## 1. Fiche session

```md
### P1-SX — profil

- Date :
- Observateur :
- Participant :
- Métier / type de production :
- Device :
- Langue :
- Production principale choisie :
- Objectif choisi :
- Stack déclarée avant parcours :
- Stack capturée par Tooltrim :
- IA déclarée :
- Suite / bundle / contrat observé :
- Outil inconnu ou usage libre :
- Reprise testée ? oui / non
- Temps jusqu’au pré-verdict :
- Session terminée ? oui / non
```

## 2. Script de verbalisation

Avant le parcours :

```md
Décris ce que tu fais vraiment. Tu peux utiliser un outil de manière imparfaite ou bizarre : Tooltrim doit le comprendre, pas te corriger tout de suite.
```

Pendant le parcours, ne poser que des relances neutres :

- “Qu’est-ce que tu comprends ici ?”
- “Qu’est-ce que tu cherchais à dire ?”
- “Tu aurais formulé ça comment avec tes mots ?”
- “Est-ce que tu décris ton existant ou une stack idéale ?”
- “Tu t’attendais à ce que Tooltrim te recommande quelque chose maintenant ?”

Ne pas dire :

- “Clique ici.”
- “Là c’est un plugin.”
- “Ce plan correspond à ton cas.”
- “Normalement cet outil sert à…”

## 4. Grille de scoring

Noter chaque dimension de 0 à 2.

| Dimension | 0 | 1 | 2 | Score |
|---|---|---|---|---:|
| Entrée par production | pense devoir choisir un logiciel | ambigu | parle de livrable / résultat | |
| Langage métier | jargon ou mauvais besoin | compréhensible mais froid | naturel pour son métier | |
| Capture vs recommandation | pense recevoir des conseils pendant la capture | doute ponctuel | comprend qu’il décrit l’existant | |
| Outil multi-usage | duplication ou confusion | compris après effort | compris spontanément | |
| Usage atypique | se sent corrigé / jugé | accepté mais flou | capturé comme réalité | |
| IA dans le flux | rubrique séparée ou absente | partielle | reliée au bon moment de travail | |
| Écosystème hôte | mauvais hôte ou mauvais plugins | utile mais incomplet | cohérent avec l’outil choisi | |
| Contrats / plans | répété, trop tôt ou bloquant | clair mais lourd | demandé une fois au bon niveau | |
| Inconnu / je ne sais pas | bloquant ou culpabilisant | possible mais peu rassurant | normal et actionnable | |
| Restitution | générique ou contradictoire | utile mais confuse | reconnue et actionnable | |

Total : `/20`.

Interprétation :

- `0–11` : session en échec produit ;
- `12–15` : utilisable avec réserves fortes ;
- `16–17` : bon candidat avec réserves ;
- `18–20` : parcours très clair.

## 5. Risques G0 à réobserver

### R1 — Moment contrat

À observer :

- la personne comprend-elle pourquoi Tooltrim parle de plan ?
- le contrat est-il demandé au niveau fournisseur/suite plutôt qu’application ?
- peut-elle dire “je ne sais pas” sans blocage ?
- un plugin gratuit/freemium donne-t-il l’impression d’un abonnement à gérer ?

Verdict :

```md
- Moment contrat : clair / lourd / bloquant
- Preuve :
- Sévérité :
```

### R2 — Suite Adobe, Canva, Maxon ou Affinity

À observer :

- sélectionner une suite ajoute-t-il mentalement toutes les apps ?
- l’utilisateur comprend-il qu’il choisit l’accès, pas les usages ?
- Tooltrim redemande-t-il un logiciel déjà couvert ?
- une app incluse est-elle vue comme coût marginal nul ?

Verdict :

```md
- Suite ou bundle : compris / ambigu / confus
- Preuve :
- Sévérité :
```

### R3 — Outil multi-usage

À observer :

- Figma, Canva, Photoshop, Illustrator, Blender ou autre est-il réutilisé sans duplication ?
- l’utilisateur comprend-il “déjà dans ta stack” ?
- l’usage secondaire est-il visible dans la restitution ?

Verdict :

```md
- Multi-usage : compris / fragile / confus
- Preuve :
- Sévérité :
```

### R4 — IA hybride

À observer :

- la personne distingue-t-elle fonction IA intégrée et outil IA séparé ?
- l’IA est-elle reliée à un résultat précis ?
- les limites, crédits ou droits sont-ils compréhensibles sans surcharge ?
- l’IA incluse est-elle rattachée au bon contrat ?

Verdict :

```md
- IA hybride : claire / partielle / confuse
- Preuve :
- Sévérité :
```

### R5 — Zones sautées

À observer :

- “non applicable” est-il respecté ?
- Tooltrim pose-t-il une question utile qui ressemble à une insistance ?
- la personne comprend-elle pourquoi une zone sautée peut revenir ?

Verdict :

```md
- Zones sautées : respectées / utiles mais lourdes / répétitives
- Preuve :
- Sévérité :
```

### R6 — Outil inconnu

À observer :

- la saisie libre est-elle visible ?
- le rattachement au besoin courant est-il compris ?
- le plan gratuit/inclus/inconnu est-il cliquable et clair ?
- l’outil revient-il dans la restitution ?

Verdict :

```md
- Outil inconnu : fluide / fragile / bloquant
- Preuve :
- Sévérité :
```

### R7 — Reprise

À observer :

- le message de reprise est-il compris ?
- les zones remplies/vides reviennent-elles ?
- la restitution reste-t-elle accessible ?
- l’utilisateur sait-il comment repartir de zéro ?

Verdict :

```md
- Reprise : rassurante / partielle / perte de confiance
- Preuve :
- Sévérité :
```

## 6. Questions post-session

À poser après la restitution :

1. “Est-ce que Tooltrim a compris ton vrai workflow ? Pourquoi ?”
2. “Quelle question t’a semblé la moins utile ?”
3. “As-tu eu l’impression qu’on te recommandait déjà des outils pendant la capture ?”
4. “À quel moment tu as pensé à tes abonnements ou plans ?”
5. “Quelle partie t’a fait gagner de la clarté ?”
6. “Quelle décision concrète tu prendrais maintenant ?”
